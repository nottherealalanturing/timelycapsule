Meridian V2 · Layer 4 · Implementation review

Primitive components, and the bug that had frozen every themed utility since T-06

Eleven primitives audited, two new ones added, and a pre-existing Tailwind misconfiguration found that had been silently freezing every themed colour to its :root value for months.

What changed

  • Two new primitives. Record — the second register as a bounded paper object, never a background. Hallmark — the mono/uppercase/tracked metadata role, the third face in Pairing C.
  • The register switch is one CSS class. .tc-record re-points the semantic tokens for its whole subtree, so any primitive nested inside re-registers with no props and no context.
  • Measured foreground tokens. --color-on-accent and --color-on-danger. Brass and danger are mid-to-light tones whose safe foreground flips with the theme; the values are computed per register rather than assumed.
  • The violet focus ring is retired. Input and OtpInput now use --color-interactive via focus-visible, so focus shows for keyboard users without firing on every mouse click. A global :focus-visible rule covers everything else.
  • OTP digits are mono and tabular, and each box now has an accessible name (Digit 3 of 6) instead of being an unlabelled field.
  • Dialog lost its entrance animation (opening is reversible → instant tier), gained a token-based scrim and a hairline border, and its title moved from serif to the instrument face — a dialog is an instrument, not a record.
  • PasswordStrengthMeter segments are square rather than pill-shaped so they read as a gauge instead of a progress bar, and the label is aria-live.

Implementation decisions

  • Themed tokens moved out of @theme inline. inline substitutes values at build time, which is correct for radius, type and easing but silently freezes anything themed. Colours and elevation now use plain @theme so the utility holds a live var() reference.
  • Only the six aliases actually in use are declared. Tailwind keys cannot collide with a token name without inline (--x: var(--x) is a cycle). Rather than invent parallel names, the colliding ones were dropped — components already consume var(--color-danger) directly, which is live anyway.
  • Elevation tokens renamed to --elev-* so --shadow-* can belong to Tailwind's theme layer. The twelve shadow-[var(--shadow-md)] call sites were converted to plain shadow-md.
  • The specimen route is dev-only, calling notFound() in production. It exists so contrast can be measured against real rendered components rather than replicas — which is exactly how both bugs below were found.
  • `destructive` keeps a filled treatment rather than becoming a bordered button. A quieter delete button tests better on aesthetics and worse on comprehension; the fix was a correct foreground token, not less affordance.

Issues discovered

  • Every themed Tailwind colour utility had been frozen since T-06. @theme inline compiled text-foreground to a literal hex from :root, so it never responded to the theme and --color-foreground did not exist at runtime at all. It was invisible in V1 because V1's :root was the light theme — so only dark mode was wrong, and only for text. Meridian V2 inverted the default and made it obvious.
  • The same class of bug hit the record register. A custom property resolves on the element that declares it, so Tailwind's aliases resolved once at :root and descendants inherited the finished colour — re-pointing tokens inside .tc-record did nothing for them. Instrument-muted text was landing on paper at 2.56:1. Fixed by re-declaring the aliases inside the scope. Rule: any scope that re-points a token must re-point its alias.
  • Two of my own measurement bugs, worth recording. The first contrast audit had an operator-precedence error that treated rgba(0,0,0,0) as an opaque background, producing three false failures. The second was a stale-computed-style artifact: mutating data-theme and reading getComputedStyle in the same script turn returns pre-mutation values, which made a working fix look broken. Both were resolved by auditing each theme in a separate page load — the values reported below come from that method.
  • Carried from layer 3 and now fixed: the primary button measured 1.54:1 and the destructive button 2.94:1. Both now use measured foreground tokens.

Inherited automatically

  • Every button, input, dialog, toast and chip across all 20+ routes picked up the corrected foregrounds, focus rings and radii with no call-site changes.
  • Light mode text became correct for the first time — the frozen-utility fix repaired every text-foreground and text-secondary in the app at once, ~408 usages.
  • Anything rendered inside a Record re-registers automatically: colours, muted tones, rules, state chips and the serif face.
  • The global :focus-visible rule gives keyboard focus to every interactive element, including ones nobody has styled yet.

Remaining work

  • Gate 2 (serif at density) is still unanswered. The specimen proves the record reads well as prose, but a real timeline and settings screen at density is the actual test. That belongs to the screen rebuild.
  • Gate 3 (ramp on real hardware) — the six steps clear AA by computation, but have not been checked on a cheap Android LCD.
  • Gate 4 (the Dual Clock) — not built. It is a composite, not a primitive, and it carries more brand than the logo.
  • No composite components yet — CapsuleCard, Composer, timeline and the reveal are still on V1 structure with V2 tokens. That is layer 5.
  • The specimen route costs ~10 KiB in the production bundle despite 404ing there. Worth excluding from the production build if headroom gets tight.
